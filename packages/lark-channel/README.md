# @ai.hermes/lark-channel

Feishu/Lark channel for Pi, built on [`@larksuite/channel`](https://github.com/larksuite/channel-sdk-node).

It connects your Feishu app to Pi, and replies to each message with a
**schema-2.0 streaming markdown card** (native typewriter effect). The assistant
text is generated by a long-lived `pi --mode rpc` subprocess and piped into the
card as the model streams.

## Session model

By default **every** message flows into the **same** Pi session (one shared
conversation), because the bot keeps a single persistent `pi --mode rpc`
process alive. To start a fresh session, the user sends:

```
/new
```

The bot intercepts `/new`, calls `new_session` on the RPC process, and replies
with a confirmation — it is never sent to the model as a prompt.

## Why this fixes the card error

Feishu's card **schema 2.0** no longer supports the legacy `tag: "action"`
element. Posting a card like:

```json
{ "schema": "2.0", "body": { "elements": [ { "tag": "action", "actions": [...] } ] } }
```

fails with:

```
ErrCode: 200861; ... ErrMsg: cards of schema V2 no longer support this capability; ErrorValue: unsupported tag action;
```

In schema 2.0, buttons must be `tag: "button"` elements placed **directly** in
`body.elements` (or inside a `column_set` layout). This package:

- streams replies via `@larksuite/channel`'s markdown stream, which emits only
  schema-2.0-valid cards (no `action` element), and
- ships `src/card.ts` with schema-2.0 card builders if you need custom buttons.

## Install

```bash
pnpm --filter @ai.hermes/lark-channel install
```

## Usage

```bash
export LARK_APP_ID="cli_xxx"
export LARK_APP_SECRET="..."
# optional:
export LARK_DOMAIN="https://open.feishu.cn"
export PI_BIN="pi"          # default
export PI_PROVIDER="openai" # optional
export PI_MODEL="gpt-4o"    # optional
export PI_CWD="."           # working dir for the pi subprocess

pnpm --filter @ai.hermes/lark-channel dev
```

## Minimal example

`examples/minimal.ts` is a standalone, runnable example using the base
`@larksuiteoapi/node-sdk` (same pattern as
[ax-feishu-bridge](https://github.com/AX1202/ax-feishu-bridge)): it receives
messages over WebSocket and replies with a **CardKit schema-2.0** card whose
button sits directly in `body.elements` (no `tag: action`).

```bash
LARK_APP_ID=cli_xxx LARK_APP_SECRET=xxx \
  node --experimental-strip-types examples/minimal.ts
```

Send the bot a message in Feishu and it replies with a schema-2.0 card. The card's
「停止」button uses `behaviors: [{ type: "callback", ... }]` and is handled by a
`card.action.trigger` handler that returns the updated schema-2.0 card.

Or programmatically:

```ts
import { createChannel, configFromEnv } from '@ai.hermes/lark-channel';

const channel = await createChannel(configFromEnv());
channel.on('message', () => {}); // optional extra handlers
await channel.connect();
```

## Card builders

```ts
import { markdownCard, streamingCard, button } from '@ai.hermes/lark-channel/card';

// schema-2.0 card with markdown + a row of top-level buttons
const card = markdownCard('## 结果\n内容', {
  buttons: [{ text: '重新生成', type: 'primary', value: { act: 'retry' } }],
});
await channel.send(chatId, { card });
```

Every builder guarantees the card contains **no** `tag: "action"` element
(`hasLegacyAction(card) === false`).

## How the Pi subprocess is invoked

The bot spawns a **single** `pi --mode rpc` subprocess and reuses it for the
whole lifetime of the channel (`src/pi-rpc.ts`). Each message enqueues a
`prompt`, and every `message_update` → `text_delta` chunk is forwarded into the
Feishu typewriter card. A turn is considered finished when the `agent_settled`
event arrives (tool calls, retries and queued continuations all settled).
Sending `/new` enqueues a `new_session` command instead of a prompt.

Operations are serialized — Pi RPC processes one turn at a time.

## Logging

Set `LARK_CHANNEL_LOG` to control verbosity (default `info`):

| Level | What you see |
|-------|--------------|
| `trace` / `debug` | pi turn settled, low-level RPC lifecycle |
| `info` | connected, inbound messages, pi prompts, replies sent |
| `warn` / `error` | pi exit, reply failures, spawn errors |

```bash
LARK_CHANNEL_LOG=debug node --experimental-strip-types src/cli.ts
```

To append logs to a file instead of stdout:

```bash
LARK_CHANNEL_LOG=info LARK_CHANNEL_LOG_FILE=/tmp/lark-channel.log \
  node --experimental-strip-types src/cli.ts
```

The same logger is handed to the channel SDK, so its internal connection/
message logs flow through the same output too.
